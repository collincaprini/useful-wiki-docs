If something fails while you are editing, preserve your work before reloading, signing out, or closing the tab. Useful Wiki keeps browser drafts, but those drafts are not permanent backups and are not synchronized between devices.

A page will not save

  1. Read the error displayed under the editor. A failed save leaves your current edits available.

  2. Choose Download draft in the error panel. Keep the downloaded HTML, Markdown, or rich JSON file until the intended changes are safely saved.

  3. Check whether the message concerns a changed file, authorization, branch rules, document size, or an unfinished image upload. Follow the matching section below.

  4. After resolving the cause, review the current page and choose Save to repository again. Look for Saved to GitHub. View commit before treating the change as published.

Download draft appears after a save error; it is not a permanent toolbar action. If browser draft storage is full before a save error appears, keep the tab open and copy content you need into another document.

Trying to save an HTML page with an empty title in the local preview produces a validation error and exposes Download draft. Restore a valid title before saving again; this example did not publish a GitHub change.

The file changed on GitHub

Useful Wiki saves against the revision you originally opened. Another browser, collaborator, or repository edit can change that file before you save. A conflict stops the save instead of silently replacing the newer file.

  1. Download your draft before reloading.

  2. Open the latest repository version and compare it with the downloaded draft.

  3. Reconcile both sets of changes, then edit the latest page revision with the result.

  4. Save again and inspect the resulting commit.

There is no automatic merge interface. Repeatedly saving the old draft does not resolve the conflict. Reloading a newer revision also does not automatically apply a draft associated with the older one. See Editing from your repository if you prefer to reconcile files with Git tools.

Recover an unsaved draft

  1. Return to the same project and page in the same browser tab while signed in as the same user.

  2. Open Edit page. When the stored draft matches the opened revision, the editor displays Your unsaved draft from this tab has been restored.

  3. Review the title and content, including every content tab, and save when ready.

Drafts are associated with your user, project, path, and original file revision. Unpublished new pages can also be recovered from that tab's session. The change-description field is not restored. A successful save clears the draft for that revision.

Cancel returns to reading and can ask you to confirm leaving unsaved work; it does not publish those changes. Browser navigation and reloads can also warn about unsaved work. Signing out clears Useful Wiki session drafts. Successful deletion clears drafts for affected pages. Save or copy needed content before either action.

The demo forgot my edits

Saved demo pages and folders use storage in the current browser. Unsaved drafts use the current tab's session. Clearing browser data, using another browser or device, or sharing a demo link does not carry your local edits with you. Use a connected repository for shared, published work.

Sign-in expired or access was revoked

  1. If a save failed, download the draft first.

  2. Choose Sign in or Sign in with GitHub and complete authorization with the account that has repository access.

  3. Open the project again and check the latest page before reapplying any preserved changes.

Sessions last at most eight hours, or less if the provider authorization expires sooner. Useful Wiki asks you to sign in again instead of refreshing indefinitely. Changing accounts does not grant access to drafts belonging to another user.

A repository or project is missing

  1. Check that you are using the correct GitHub account and can open the repository directly in GitHub.

  2. When choosing a repository under New project, use Load more repositories if it is not in the currently loaded list. The filter searches loaded entries.

  3. Check any organization approval or SSO authorization required for the OAuth app.

  4. Confirm that the repository has been registered as a Useful Wiki project. A repository's existence alone does not create that registration.

A new registration requires write access. An already registered repository opens its shared project rather than creating another project with different settings. Archived repositories cannot be newly selected for writing. Public projects can be read by anonymous visitors through a direct link; private projects require the visitor's GitHub access.

On This project isn't available, use All projects to return to the dashboard or Sign in with GitHub to authorize access. A not-found response can mean either a missing repository or insufficient access. See Sharing and access.

A page or folder cannot be opened

  1. From We couldn't open this location, choose Back to project and look for the current entry.

  2. Check whether the file or folder was renamed, moved, or deleted. Old links are not automatically rewritten by a move.

  3. Check the project's selected branch and configured content folder. The page must exist inside that folder on that branch.

  4. If the page exists but still cannot be read, check its format and size using the limits below.

Page addresses retain the full file path and extension. Changing only the displayed title does not change the address. The shared asset directory is intentionally excluded from page navigation and search.

I can read but cannot edit or save

Editing actions require GitHub write access, and archived repositories are read-only. A user's ability to read a private project does not imply permission to change it.

  1. Check repository write permission, organization authorization, and whether the repository is archived.

  2. Check the branch shown in the sidebar against GitHub's branch rules. A protected branch may require a pull request and reject a direct commit.

  3. If the branch requires a different workflow, make the change through the repository's GitHub process and reload the published result in Useful Wiki.

Useful Wiki does not bypass branch protection or provide a pull request interface. Project settings cannot currently be edited in the app, so do not look for a branch-switching settings control. A save error can also indicate that a newly created file path already exists; choose a unique path or edit the existing page.

An image will not upload or display

  1. Use a supported PNG, JPEG, GIF, WebP, or AVIF file no larger than 900,000 bytes. Resize or compress larger images before adding them.

  2. Wait for Adding image… to finish before saving. If the placeholder says Image could not be added or the upload was interrupted, remove that placeholder and add the image again.

  3. Check repository write access and branch rules if the upload is rejected. Image uploads create their own commits.

  4. If an existing image is missing after a move, check the relative image path against the page's new folder.

Uploads go into the shared assets directory beneath the project's content root. Canceling the page edit or removing its image does not delete an already uploaded repository file. Private image access follows repository authorization. SVG and executable image content are not supported.

Markdown source mode does not show the rich image-upload controls. Add a portable image reference to an existing repository asset, or use the repository workflow described in Images and links.

A rename, move, or deletion failed

  1. Save or cancel active edits inside an item before renaming or moving it.

  2. Choose an existing destination folder inside the configured content root. Avoid occupied paths, a folder's own descendants, and file-format changes.

  3. If the destination already has a local draft, open and resolve that draft first.

  4. If the previewed file or folder changed, inspect its current contents and reopen the operation's preview before trying again.

The configured content root cannot be deleted. Folder operations include all descendants, including images and files absent from navigation. Successful moves preserve file contents, so update inbound links and relative links or images manually. See Organizing pages for the complete workflows.

Search or backlinks look incomplete

Typing in search filters current titles and paths. Enter at least two characters and choose Search content to inspect page bodies. Search and backlink discovery scan up to 60 supported pages on demand and report partial results. Invalid or oversized pages can also make a scan incomplete.

Backlinks are available in Wiki mode through Find pages that link here. Discovery recognizes repository page paths; full hosted URLs may open correctly without appearing in those lists. There is no background content index. See Navigation and search.

Clipboard, editor, or network controls fail

  • Copy as Markdown: if clipboard access is blocked, copy the selected text from the Copy page dialog.

  • Copy link: copy the address from the browser if the clipboard action fails. For code, select the code and use Ctrl+C or Cmd+C.

  • Monaco fails to load: a plain editor remains available for Markdown or code. Preserve your text and save normally; syntax highlighting and richer editing commands may be unavailable until loading succeeds.

  • GitHub rate limiting or a temporary service error: preserve any draft, wait, then retry. Anonymous reading uses GitHub's unauthenticated rate limits.

  • Fullscreen fails: retry through the fullscreen button, dismiss its error, or keep working in the normal window. Unsupported browsers show a disabled control.

Current limits and unsupported workflows

  • Documents are limited to 700,000 bytes. Split large pages into smaller linked documents. Images are separate files with a 900,000-byte upload limit.

  • The repository browser rejects a recursive file tree that GitHub reports as truncated. Use a smaller documentation repository; selecting a narrow content folder does not avoid the initial whole-repository tree request.

  • Supported pages are HTML, Markdown, and existing version-1 .wiki.json documents. Marked HTML uses format version 1 and a title of 1–200 characters. Arbitrary website HTML, MDX execution, scripts, iframes, and executable embeds are unsupported.

  • Use an ordinary GitHub repository. GitHub's built-in .wiki.git repository is not the target format.

  • There is no automatic merge, live co-editing, suggestions flow, pull request interface, project settings editor, or custom-domain setup in the app.

For an installation that cannot sign in at all, its operator can use Running locally and deployment setup. Return to Writing and saving pages once the issue is resolved.
