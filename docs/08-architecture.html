Useful Wiki is a Next.js application over ordinary GitHub repositories. The browser talks to Next.js; the server talks separately to GitHub for content and authorization, and PocketBase for identity and project metadata.

Sources of truth

  • GitHub: published pages, images, branches, history, and repository permissions. HTML is the complete source for an HTML page, with no synchronized JSON sidecar. Markdown and existing versioned .wiki.json documents retain their formats.

  • PocketBase: uw_users identities and uw_projects registrations. One shared project selects a repository, branch, content folder, and Documentation or Wiki mode. Both collections have locked API rules.

  • Browser: unpublished drafts and personal preferences. Demo content occupies a separate local-storage namespace and never mutates connected services.

Authorization on each request

Next.js exchanges GitHub OAuth credentials and seals the caller's access token in an encrypted, HttpOnly, SameSite cookie. Sessions last at most eight hours or the provider's earlier expiry. GitHub tokens and repository contents never enter PocketBase; its service credential authorizes metadata operations only.

The server checks GitHub access before exposing project metadata, pages, images, search, or backlinks. Public repositories support anonymous reads. Private repositories require the visitor's GitHub authorization, and writes require their write access. Creator identity and cached visibility grant no access. Stable repository IDs survive renames and transfers.

GitHub requests use the caller's OAuth token, with no shared token or installation-token fallback. Content and project APIs use no-store; private images avoid a shared image optimizer. Mutations check the request Origin and bound JSON bodies. GitHub branch protection still applies.

Saving and recovering

Saving publishes a Git commit using the original file SHA. A changed revision causes a conflict; the app never substitutes a newer SHA to force an overwrite. Drafts retain their original revision in sessionStorage, keyed by user, project, and path. Failed saves preserve them; explicit sign-out clears them. There is no automatic merge interface.

Folder creation adds a hidden .gitkeep. Moves and deletions check the file or previewed folder revision, publish one commit, and never force a branch update. Paths stay inside the configured content root. Moves preserve file contents, so affected links need manual updates.

Assets and discovery

Uploads commit immediately to the reserved assets/ directory beneath the content root. Cancelling a page edit leaves uploaded files in GitHub. Relative references keep images portable. Raster uploads are limited to 900 KB; documents to 700 KB. Search and backlinks scan up to 60 supported pages on demand and label partial results. Truncated repository trees are rejected.

Code map

src/app/api defines request handlers; src/lib/server handles authorization and persistence; src/components integrates the UI. src/editor is a reusable editor snapshot, independent of GitHub, PocketBase, and app authentication.
