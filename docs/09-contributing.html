Contribute documentation in useful-wiki-docs and application changes in useful-wiki. Keep each change in its intended repository, describe the problem it solves, and review the diff before sharing it.

Improve the documentation

These pages are the documentation and a real Useful Wiki content set. Edit them through the visual editor or directly as HTML, following the repository editing guide. Preserve UTF-8, the version-1 format marker, page titles, and supported document elements.

Keep instructions tied to current behavior. Verify button labels, file paths, commands, and limits against the app or its source. Explain consequences such as immediate commits, draft recovery, and links affected by moves. Avoid publishing credentials, private repository information, or another installation's service configuration.

Check relative links and open changed pages in Useful Wiki. Review headings, lists, code spacing, and narrow-screen reading. When changing filenames or folders, update affected page links and image references. Preserve readable structural lines rather than reflowing whole paragraphs.

Change the application

Start with local setup and the app's AGENTS.md. Before writing Next.js code, read the relevant guide inside the installed node_modules/next/dist/docs/. The installed version's APIs and conventions take precedence over remembered examples; keep the generated Next.js instruction block.

Read the trust boundaries before changing data access. Preserve caller-authorized GitHub requests, locked PocketBase metadata, private-content checks, original-SHA saves, and local-only demo behavior.

src/editor is a snapshot of the separate js-html-editor component. Read EDITOR_SOURCE.md and src/editor/README.md before changing it. Keep application authentication, GitHub persistence, image transport, and draft management in the host integration. Coordinate reusable editor changes explicitly instead of silently modifying sibling checkouts.

Validate the behavior

For meaningful application changes, run:

npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build

Unit/API tests mock GitHub. Add coverage for the behavior or regression you changed, especially permissions, conflicts, paths, and content validation. Browser tests exercise the demo and editor; Playwright currently uses installed Microsoft Edge and port 3001. Adjust its channel for your browser, and include relevant keyboard and mobile checks for UI work.

PocketBase integration checks belong on an isolated local database. node scripts/check-pocketbase.mjs reads .local/pocketbase-test.json, requires 127.0.0.1, and expects the schema to be initialized. Report the checks actually run and any remaining gaps.

Share the change

Use the repository's GitHub contribution workflow for review, including pull requests where appropriate. Useful Wiki itself saves commits directly to the selected branch and has no pull-request or suggestion interface. Describe the resulting behavior and validation so a reviewer can assess the change without this conversation.
